Wie stellt man ein Bankkonto im Computer dar? Objekte, Attribute, Zustände und Objektdiagramme

Input Baustein 2, ca. 15 min. Ziel: Am Ende können alle ein Objektdiagramm lesen und zeichnen, kennen den Begriff Zustand und haben eine Objektreferenz gesehen. Danach Etappe 2.A (Aufgaben 2.1–2.3).

Steuerung: Pfeiltasten oder Leertaste, N Notizen, M Menü, F Vollbild, B Schwarzbild.

RückblickWo wir stehen

Die Verb-Substantiv-Methode hat aus der Anforderung zwei Kandidaten geliefert:

Kunde Konto

Beide haben Daten – Name, Kontostand, PIN …

Beide haben Fähigkeiten – einzahlen, abheben, Name ändern …

Die Idee der Objektorientierung

Was zusammengehört, wird in einem Objekt gebündelt: die Daten und die Fähigkeiten eines Kontos an einer Stelle.

Erinnerung an 0.2: Dort waren Kontostände und Funktionen über das ganze Programm verstreut.

Kurz an Baustein 1 anknüpfen: Ergebnis der Kandidatentabelle zeigen (Kunde, Konto). Bezug zur Mängelliste aus 0.2 herstellen (verstreute Daten, kopierte Funktionen).

BegriffEin Objekt: das Girokonto von Herrn Lehmann

Daten

  • Kontonummer 987654321
  • PIN 1234
  • Kontostand 2.020,00 €
  • Dispo 500,00 €

Fähigkeiten

  • Geld einzahlen
  • Geld abheben
  • Geld überweisen
  • Kontostand abfragen
Objekt = Daten (Attribute) + Fähigkeiten (Methoden).
Jedes Objekt hat eine eigene Identität: Das Konto von Frau Schulz ist ein anderes Objekt – auch wenn es dieselben Werte hätte.

Bewusst Alltagssprache links, Fachbegriffe erst im Merkkasten. Impuls: „Was muss die Bank über ein Konto wissen, was muss ein Konto können?“ – Schülerantworten abwarten, dann aufdecken.

Zustand 1

Alle Attributwerte zusammen bilden den Zustand eines Objekts.
Methoden ändern den Zustand – das Objekt bleibt dasselbe.

Knöpfe vom Kurs ansagen lassen. Vor abheben(3000) vorhersagen lassen: Laut Anforderung darf der Kontostand höchstens auf −500 € fallen. Die Simulation lehnt deshalb ab, wenn der Kontostand danach unter −500 läge.

Eine Klasse ist der Bauplan für gleichartige Objekte. Aus einer Klasse werden beliebig viele Objekte erzeugt.

Jeder Schritt verwandelt das Objektdiagramm ein Stück. Wichtig: Die Klasse hat keine Werte – deshalb Datentypen.

EntscheidenDatentypen: Text, Zahl oder Wahrheitswert?

Zwei Prüffragen

  1. Wird mit dem Wert gerechnet oder der Größe nach verglichen? → Zahl
  2. Kann er mit 0 beginnen oder Buchstaben, Leer- und Sonderzeichen enthalten? → Text

Nur zwei mögliche Werte, ja oder nein? → Wahrheitswert

Beispiele bewusst außerhalb von Aufgabe 3.3 gewählt (dort: Kontonummer, PLZ, Telefonnummer, IBAN …).

Parameter – nur während __init__

Mit Pfeiltaste oder „Schritt“ durchgehen. Kernaussagen: self ist das neue Objekt; self.name = name kopiert den Parameterwert ins Objekt; Parameter verschwinden nach dem Konstruktor, Attribute bleiben. Anschließend dasselbe in Thonny mit dem Debugger (Strg+F5, dann F7) zeigen.

KonstruktorNicht jedes Attribut ist ein Parameter

class Geldautomat:    def __init__(self, standort):        self.standort = standort        self.bargeld = 50000.0        self.akt_konto = Noneautomat1 = Geldautomat("Kröpeliner Straße")
automat1 : Geldautomat
standort = "Kröpeliner Straße"
bargeld = 50000.0
akt_konto = None
  • Was für jedes Objekt anders ist, wird als Parameter übergeben
  • Was für alle neuen Objekte gleich ist, setzt der Konstruktor selbst: fester Startwert
  • None: Das Attribut verweist (noch) auf kein Objekt

Übertrag in 3.6: Laut Anforderung startet jedes Konto mit 0,00 € und hat 500 € Dispo. Welche Attribute werden also Parameter? – nicht vorwegnehmen.
